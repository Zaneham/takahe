2026-08-21  Module instantiation, which had not worked since April
  - 8182188 made instance port wiring directional and read the
    direction off nets[pnet].is_port. The instance path had already
    set that to zero on purpose, since an inlined child's ports are
    not the top level's, so neither branch fired and every connection
    was dropped without a word. lw_pdir reads the direction from the

    that is not a port now warns rather than vanishing.
  - Under that sat an older one. Instance nets are created as u_name,
    but lw_fnet looked up the bare name, missed, and invented a fresh
    net at the wrong width, so the child's body was never joined to
    the instance at all. The context carries the prefix now, and does
    not cache the lookup, because two instances share those AST nodes.
  - always_ff inside an instance made no flop. The instance path kept
    its own copy of the always loop and skipped the redirect flush, so
    the chain never drove the target net. One lw_alwy, three callers.
  - Those flops then had no clock, because lw_dffs only read the top
    module's sensitivity lists. lw_ckrs runs over each expanded
    instance too, with its prefix set.
  - picorv32 goes from 257 cells to 8,090 with 210 flops. The 3,305
    in the README was measured honestly but came off the old
    bidirectional wiring sitting on top of the net bug, so it was
    never the right number either. dozenal_alu, minuteman_d17b and
    voyager_fds land exactly on their published counts. qsim, ruru
    and setun70 have moved and want re-measuring.
  - tools/synth-gate.sh checks every design against a cell floor,
    wired into CI. The unit tests could not see a whole design

2026-08-10  JEDEC fuse maps, a 74LS target, and an emitter that meant it
  - jd_read parses JESD3-C, the format PLD programmers write. Fuse
    states only. Both checksums are compared, and a mismatch is
    recorded rather than fatal, because it is nearly always a
    truncated download and the fuses are still worth reading. The
    F default fills only what no L field touched, whatever order
    the fields arrive in.
  - lib/ttl7400.lib, the 74LS series as a technology library. Area
    is packages rather than micrometres: a 74LS00 is four 2-input
    NANDs in one DIP, so a NAND costs 0.25 of a chip and the
    area-driven mapper minimises parts on the board with no new
    code. Fourteen cells, typical 74LS delays.
  - Writing it flushed out four things the PDK flow had hidden.
    lw_dffs only walked always_ff, so every flop from a plain
    always @(posedge clk) got net 0 as its clock and the emitter
    printed 1'b0. The emitter also deduplicated wire declarations
    on the base net name while emitting indexed names, so
    out_mapped.v had 381 declarations for 2,769 wires. The target
    comment was hardcoded to sky130, and area printed as %.0f
    labelled um2 whatever the library meant by it.
  - Tests print in category then name order. Registration runs
    through constructors, whose order follows the link line, so the
    output used to reshuffle whenever a file was added.
  - Three fixtures describe themselves, after the z390 sort tests
    where each record states its own position. The fuses in jd_says
    spell JEDEC OK, every byte in jd_addr holds its own index, and
    parts.sv names each output after the part that should drive it.
    Break one and the failure prints mojibake rather than expected
    1 got 0. Each was checked by breaking what it guards. 145 tests.

2026-08-08  SAT-backed equivalence checking
  - cn_mod encodes a bit-level combinational module to CNF, and
    cn_mitr builds a miter of two of them: inputs tied together,
    outputs XORed, assert some pair differs. Unsatisfiable means
    no input tells them apart, which is what equivalence means.
    Gate clauses come from a computed truth-table mask reusing the
    same row generator the library cells go through, so there is
    one place to be wrong rather than nine.
  - --equiv now tries the miter before falling back to vectors.
    Where it applies, "PASS" stops meaning "100,000 random vectors
    failed to find a counterexample" and starts meaning proved.
  - It refuses rather than guesses. A module holding wide operators
    that were never bit-blasted, or latches or memories, returns
    "not encodable for SAT" and drops to simulation with that said
    out loud. Ordinary word-level RTL still takes the vector path,
    so the proof currently applies to bit-level designs: recovered
    netlists, and anything already bit-blasted. Wiring mp_bblst
    into the flow is what would extend it to the rest.
  - Two miter tests: one proves a XOR equivalent to (a|b)&!(a&b),
    one checks a XOR against an OR and requires the solver to
    produce the distinguishing input. A miter that cannot fail is
    not a proof of anything. 126 tests.

2026-08-07  SAT solver: decision heap and phase saving
  - tk_sat.c picked its branching variable by scanning every
    variable's activity. Fine at a few hundred variables, ruinous
    at eighty thousand, which is the size that matters. Now a
    lazy binary max-heap: activity bumps percolate up, backtracking
    returns variables to the heap, and assigned variables are
    skipped on the way out.
  - Phase saving. Restarts throw away the search tree, and used to
    throw away everything learned about which way each variable
    wants to sit as well. Decisions now reuse the last value the
    variable took.
  - Together these take the 695k-clause netlist inversion from
    "gives up" to solved in 16.5 seconds, verified by simulating
    the returned model back through the design. Cadical still does
    it in 0.8s, so there is a good way to go, and learnt clause
    deletion is the obvious next piece.

2026-08-07  VHDL clocked processes were never clocked
  - FIX: every VHDL flop came out with its clock tied to net 0.
    VHDL puts the edge inside the process body rather than in the
    sensitivity list, and vp_proc wrote a placeholder sensitivity
    edge with a string offset of zero. The lowerer compared that
    against "posedge", never matched, and left clk unset. Nothing
    tested it, so it sat there.
  - vp_proc now looks ahead into the body for rising_edge(x) or
    falling_edge(x), names the clock from it, and emits a real
    posedge sensitivity edge. Signals in the sensitivity list that
    are not the clock become the async reset, which is what
    `if rst_n = '0'` before the edge test means, so the smoke test
    now produces RT_DFFR with clk and rst_n properly connected
    rather than RT_DFF with neither.
  - falling_edge() now works. The parser marks it "negclk" rather
    than "negedge", because the lowerer reads negedge as async
    reset and the two would be indistinguishable. On seeing
    negclk the lowerer inserts a clock inverter and clocks the
    flop from that, so RT_DFF stays posedge-only and no consumer
    of the cell enum has to change.
  - A clocked process with no edge function is also refused, since
    there is then nothing to identify the clock from.
  - Two regression tests: one asserts the flop's clock input is
    the clk net and the reset is rst_n, one asserts falling_edge
    raises an error. 124 tests.

2026-08-07  SAT solving, CNF encoding, and preset flops
  - New src/opt/tk_cnf.c: Tseitin encoding of a recovered netlist
    into CNF, with k-cycle unrolling so a question about a
    sequential design becomes a question a solver can answer.
    Time becomes space. Each cell contributes 2^n clauses from
    its truth table, which for standard cells is 32 at worst.
    cn_unrl takes a list of input nets to make free and a list
    of nets to watch, so constraints can be placed on what the
    design does over time and not only on one signal at the end.
    DIMACS output via cn_dmcs for feeding external solvers.
  - New src/opt/tk_sat.c: CDCL SAT solver. Two watched literals,
    VSIDS activity, first-UIP conflict learning, Luby restarts.
    In-tree and dependency-free, because pulling in MiniSat would
    mean a C++ toolchain for about four hundred lines of
    bookkeeping. Solves the warm-up inversion (find the input that
    asserts an output) correctly.
  - Known limitation, stated plainly: tk_sat.c has no learnt
    clause deletion, no phase saving, and picks its branching
    variable by linear scan over activity. That is fine for small
    instances and gives up on a 700k-clause one, where Cadical
    finishes in under a second. A decision heap and clause
    database reduction are the next work.
  - FIX: preset flops were modelled as starting at zero. sky130's
    dfstp has `preset : "!SET_B"` in its ff group, so it comes up
    at ONE. The Liberty loader looked for a pin called RESET_B,
    found SET_B, and emitted a plain flop with no asynchronous
    input at all. lb_cell_t gained set_pin, there is a new RT_DFFS
    cell type carrying the async set, and both tk_sim.c and
    cn_unrl now start those flops high. Same shape as the
    falling-edge binding bug: Liberty said so, the loader parsed
    it, and the value was discarded.
  - tk_seqr.c and the emitters know about RT_DFFS.
  - 122 tests, up from 117.

2026-08-07  Netlist reading, cell semantics from Liberty, and a
            cycle simulator
  - New src/tech/tk_lfn.c parses Liberty function expressions
    properly and evaluates them into cd_cell_t truth tables.
    Shunting-yard to RPN then an iterative stack walk, so no
    recursion and every loop bounded. Handles Liberty's implicit
    AND ("A1 B1"), postfix negation ("A'"), both spellings of
    each operator, and bare 0/1 constants. 347 of SKY130's 428
    cells now build an exact truth table. The 81 that don't are
    63 sequential and 18 physical fill, which is precisely the
    set that shouldn't.
  - tk_bind.c no longer classifies cells by string-matching
    their function against nineteen hardcoded patterns. It
    builds the truth table and compares tables instead, which
    is how a31o and friends stop being invisible. Mapped output
    for existing designs is unchanged, so this is a change of
    method rather than of result.
  - FIX: mp_bind could bind RT_DFF and RT_DFFR to a falling-edge
    cell. dfrtn_1 is 25.02um2 and clocks on !CLK_N; dfrtp_2 is
    26.28um2 and clocks on CLK, so choosing on area alone picked
    the wrong edge. RT_DFF means posedge. lb_cell_t gained
    negclk, set from the clocked_on expression the loader was
    already parsing and discarding, and mp_bind skips those
    cells. tests/out_mapped.v changes accordingly: eight flops
    that were dfrtn_1 are now dfrtp_1. Designs synthesised
    before this sampled on the wrong clock edge.
  - FIX: mp_bind also bound ordinary logic to special-purpose
    cells. lpflow_inputiso1p_1 is an isolation cell whose
    function is (A|SLEEP), which is an OR by truth table and
    emphatically not an OR by intent. lb_cell_t gained special,
    set from is_isolation_cell, is_level_shifter, always_on and
    clock_gating_integrated_cell, and those cells stay out of
    the binding table.
  - New --netlist mode reads a structural gate netlist. The SV
    parser already handled module instantiation, so this is a
    second resolution path in the lowerer: an instance matching
    no module is looked up in the Liberty library instead of
    being shrugged off as a black box. Combinational cells
    become RT_LUT carrying their truth table; flops keep their
    own type and remember which part they were.
  - New RT_LUT cell type plus rt_cell_t.cdix, which indexes the
    cd library. Sits in what used to be padding, so rt_cell_t
    is the same size it was.
  - New src/xform/tk_seqr.c recovers sequential structure. Walks
    each flop's D cone back to whichever flops feed it, then
    classifies: fed by one other flop is a shift stage, fed by
    several is real state. Self-reference is tracked separately
    from external sources, which is what stops an enable mux
    from obscuring a shift register. Also groups flops by shared
    control signals, after HAL's DANA. Reported by --seq.
  - New src/xform/tk_sim.c simulates a recovered netlist.
    Two-valued, zero-delay, one posedge domain. Combinational
    logic settles by iterating to a fixed point and reports
    failure to settle rather than truncating, because a
    combinational loop is worth knowing about. All D inputs are
    sampled before any Q moves, so shift registers shift by one
    rather than racing to the end.
  - em_vlogn emits recovered cells, so a netlist read in comes
    back out as the same cells. Read, emit and re-read gives
    identical net count, cell count and register structure.
  - FIX: escaped identifiers were emitted without their
    terminating whitespace. A Verilog escaped identifier runs
    from the backslash to the next space, so "\a_reg[0]_7)"
    swallowed the bracket and the paren with it. Anything
    consuming the emitted netlist, OpenROAD included, would
    have choked on names carried over from a netlist.
  - FIX: adding a cell type read one past the end of the
    ctnames[] table in tk_rtl.c and printed a garbage pointer,
    because nothing forced that table to agree with rt_ctype_t.
    There is now a compile-time size assertion, so the next
    person gets a build error rather than a crash three files
    away.
  - 117 tests, up from 106.

2026-05-19  Memory primitive library and iCE40 BRAM emission
  - New defs/mems_ice40.def describes iCE40 memory primitives
    in a definition-driven grammar: name, type, address bits,
    supported widths, total size, init capability, cost, and
    per-port flags for clock polarity, write enable, read
    enable, clock enable, byte enable granularity, active-low
    semantics, and the iCE40 three-LSB address-bit-swap quirk.
    Two primitives ship today: SB_RAM40_4K (cost 100) and
    SB_SPRAM256KA (cost 200, so BRAM wins for anything that
    fits in a 4Kbit tile). New families like SKY130 SRAM or
    ECP5 BRAM are a text file each, not a recompile.
  - New src/map/tk_mmap.c implements the .def loader
    (ml_load), the matcher (mm_fit, mm_pick), and the
    public entry point (mp_mmap) that walks rt_mod_t.mems[]
    and tags each entry with the lowest-cost primitive that
    fits, leaving unmappable memories untouched so the soft-
    logic path still emits them as before. About 270 lines,
    JPL-style with bounded loops and no allocations after
    init, HLASM-style 4-7 character function names.
  - rt_mod_t.mems[] gained prim_set and prim_idx fields so
    the FPGA emitter can ask "did this memory get mapped"
    without re-running the matcher.
  - src/map/tk_fpga.c now emits one SB_RAM40_4K instance per
    mapped memory, with proper RDATA/WDATA/RADDR/WADDR
    connections derived from the corresponding RT_MEMRD and
    RT_MEMWR cells, read and write clocks pulled from the
    design's input port whose name contains "clk", read and
    write enables tied to the appropriate signals, and the
    READ_MODE/WRITE_MODE parameter chosen to match the
    memory's data width (mode 0 for 16-bit, 1 for 8-bit,
    2 for 4-bit, 3 for 2-bit). RT_MEMRD and RT_MEMWR cells
    whose memory was mapped are skipped in the regular
    cell-emission loop so they do not produce duplicate
    cell entries.
  - main.c loads the iCE40 library and runs mp_mmap before
    fp_json whenever --fpga is in use. Loading and matching
    are no-ops on designs without memories so other --fpga
    runs are unaffected.
  - tests/sram.sv is a new minimal test design exercising
    the canonical sync RAM pattern (gated write, indexed
    read) that the matcher handles correctly end to end,
    producing a complete BRAM instance in the nextpnr JSON.
  - tests/tmmap.c lands fourteen regression tests under the
    "mmap" category, taking the total from 87 to 101.
    Covers loader behaviour on the real .def file and on a
    crafted small .def, missing-file failure, primitive
    field accuracy for both shipped primitives, port flag
    parsing, comment and blank-line tolerance, matcher
    decisions for fits-both, too-wide, falls-through-to-
    SPRAM, too-deep-for-everything, and multi-memory
    modules, plus full-pipeline CLI tests verifying the
    BRAM instance appears in the JSON for sram.sv, does
    not appear for non-memory designs like smoke.sv, and
    that the bilingual catalogue still loads when --fpga
    and --lang mi are combined.
  - Known limitations carried forward: the lowerer does
    not yet produce RT_MEMWR cells for writes that live
    inside deeply nested control flow (case + if + always_ff,
    as in tests/bigger.sv), so the FIFO test design maps
    its memory but the BRAM instance ends up with WDATA
    and WADDR hooked to the sentinel net. This is a
    pre-existing lowerer gap rather than a mapper bug and
    will be addressed when the always-block lowerer path
    learns to track memory-write context. The iCE40
    address-bit-swap quirk is described in the .def schema
    but not yet applied in the emitter; combined with
    incomplete clock-domain tracking, the emitted JSON is
    structurally correct but not yet routable by nextpnr
    without manual adjustment. Real utilisation-aware cost
    model is also a v2 item; today's cost is a plain
    integer that does not account for tile efficiency.

2026-05-14  Synthesis fingerprint (--hash)
  - New --hash flag prints a 64-bit deterministic digest of
    the synthesised netlist to stdout, formatted as
    "hash: %016x", so that two runs of takahe on the same
    input source produce byte-identical digests and any
    divergence between runs surfaces as an immediate hash
    mismatch rather than as silent non-determinism that only
    becomes visible when somebody tries to reproduce a build
    months later.
  - The underlying algorithm is FNV-1a 64-bit, chosen because
    it fits in twelve lines, has zero external dependencies,
    and is more than sufficient for the question being asked,
    which is "did these two synthesis runs produce the same
    netlist" rather than "can an adversary forge a collision";
    a future bump to SHA-256 is a drop-in replacement should
    a stronger fingerprint ever become necessary.
  - The canonical byte stream consumed by the hash covers
    every net's width, radix, port role, and driver index,
    followed by every cell's type, width, output net, input
    arity, input net indices, and parameter value, walked in
    array order with index 0 reserved as the pool sentinel as
    is the convention everywhere else in the codebase.
  - Net names and cell names are deliberately excluded from
    the canonical form because a wire renamed from q to q_r
    is the same hardware and the fingerprint should agree;
    generation counters and other runtime bookkeeping are
    likewise excluded for the same reason.
  - Slots vacated by deletion passes (cells whose type has
    been overwritten with the RT_CELL_COUNT sentinel) are
    folded into the hash as a single zero byte so that
    deletions remain distinct from rewrites and so that
    reordering passes never accidentally collide.
  - The canonical form carries a version byte (HS_VER, set to
    1 in this release) which must be bumped any time the set
    of fields included in the hash or the order in which they
    are emitted changes, on the principle that saved digests
    become meaningfully invalid the moment the form changes
    and the version byte ensures the divergence shows up at
    the very first byte rather than as a confusing mid-stream
    collision much later.
  - Smoke verification on tests/smoke.sv produces the digest
    5e2f63ed79b19097 reproducibly across consecutive runs,
    tests/bigger.sv produces 8c4d1dacdbf02ee0 reproducibly
    both before and after optimisation since op_opt finds no
    work on that particular design, and designs/voyager_fds.sv
    correctly diverges from 40a6def1e6c5fc0e pre-optimisation
    to fadd81c343371411 after the optimiser applies its 24
    transformations, confirming that the hash both holds
    steady when the netlist holds steady and changes when the
    netlist changes.
  - Implementation lives in src/emit/tk_hash.c at roughly 125
    lines, uses the hs_ file prefix consistent with the rest
    of the emit directory, exposes mp_hash as the public
    entry point in include/takahe.h alongside mp_blif and
    mp_yosys, and compiles cleanly under the full project
    warning gauntlet of -Wall -Wextra -Werror -pedantic plus
    twelve additional diagnostics.
  - All 76 existing tests continue to pass with no regression
    introduced by the new flag or its supporting code.
